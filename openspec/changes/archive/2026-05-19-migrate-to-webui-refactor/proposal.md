## Why

当前项目以 CustomTkinter 桌面窗口为主界面，UI、事件处理、后台任务、配置和日志展示耦合较重，继续叠加功能会让维护成本快速上升。迁移到 WebUI 可以获得更现代的交互体验、更清晰的前后端边界，并为后续任务监控、配置管理和流程优化打基础。

## What Changes

- **BREAKING**: 将主交互入口从桌面 GUI 迁移为本地 WebUI；原 `run_gui.py` 不再作为主要功能入口，后续可保留为兼容启动器或迁移提示。
- 新增浏览器端工作台，覆盖小说总结、文章总结、自定义总结、章节分割、提示词编辑、API 配置和日志查看等现有核心工作流。
- 新增后端服务层，将现有 `logic/` 中的总结、拆章、提示词、状态和 API 调用能力封装为 WebUI 可调用的接口。
- 重整任务运行模型，统一小说总结、文章总结、自定义总结和章节分割任务的启动、暂停、取消、状态查询和日志流。
- 梳理配置与持久化逻辑，减少 GUI 控件状态直接驱动业务流程的情况。
- 新增项目署名展示，标明原作者 `zhoufei_1314` 和现作者 `Ice_wilderness`。
- 输出一组待确认的代码逻辑优化点，先由用户判断范围，再进入实施。

## Capabilities

### New Capabilities

- `webui-workbench`: 定义本地 WebUI 工作台的页面、导航、表单、日志和任务控制行为。
- `task-runtime-api`: 定义 WebUI 与后端任务运行时之间的接口，包括启动、暂停、取消、进度、日志和结果状态。
- `configuration-management`: 定义 API 配置、提示词、字数设置和任务缓存等配置/状态的读取、保存和迁移行为。

### Modified Capabilities

- 无；当前仓库没有既有 OpenSpec capability，本次以新增规格建立行为契约。

## Impact

- 受影响代码：`run_gui.py`、`gui/`、`logic/`、`splitters/`、`config.py`、`requirements.txt`。
- 可能新增代码：Web 后端入口、接口路由、任务服务、配置服务、前端应用目录、静态资源与启动脚本。
- 可能新增依赖：轻量 Web 后端框架、WebSocket/SSE 支持、现代前端构建工具与 UI 组件库；具体选择在实施前确认。
- 迁移风险：现有桌面 GUI 事件处理和后台线程逻辑需要拆分，必须保证已有总结流程、断点续跑、缓存目录、提示词编辑和多 API 并行能力不退化。
