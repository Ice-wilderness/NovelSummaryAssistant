## Context

`call_llm_api` 在同一个请求辅助函数中分别处理流式 SSE 和非流式 JSON。两条路径都假定 `choices` 至少包含一个对象并直接读取首项；流式路径只捕获 JSON 解码失败，因此 OpenAI 兼容服务发送的 `choices: []` 元数据分块会越过现有错误处理并触发 `IndexError`。流式内容缓存在单次尝试的局部列表中，一旦发生该异常，已接收内容会随整次请求重试而丢弃。

现有外层循环已经统一负责记录失败、延迟重试以及耗尽尝试后返回 `APIPermanentError`。本变更应复用该边界，避免引入新的公共异常或配置。行为要求见 `specs/llm-api-response-parsing/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在任何列表索引或字段访问前，对聊天完成响应的必要结构进行显式校验。
- 区分流式元数据空 choices 与非流式空最终响应，并分别采取跳过或受控失败策略。
- 让流式与非流式顶层 API 错误使用一致、可读的上游错误消息。
- 保留现有首候选项语义、内容校验链、重试次数和成功返回结构。

**Non-Goals:**

- 不增加多候选项选择或合并能力。
- 不向调用方暴露 token usage，也不新增流式统计接口。
- 不重写通用 SSE 客户端，不支持非 OpenAI 兼容的专有响应格式。
- 不改变 API 配置、提示词、超时或重试参数的含义。

## Decisions

### 1. 使用共享的小型响应结构校验逻辑

在请求函数内部集中完成三项检查：顶层值必须是对象；非空 `error` 必须先于 choices 处理；`choices` 必须是列表且首项必须是对象。错误对象为映射时优先取 `message`，否则使用其字符串表示。结构不合法时抛出带上下文的 `ValueError`，由既有外层循环记录和重试。

这样可以消除两条路径中重复且不一致的索引假设，同时保持改动局限在当前模块。备选方案是在每个分支分别加 `if not choices`；该方案虽然能修复当前空列表，但容易继续遗漏顶层非对象、非列表 choices 或非对象首项，并让错误消息再次分叉。

### 2. 空 choices 的语义由响应模式决定

流式分块的 `choices: []` 返回“无内容候选”的结果，调用方直接继续读取下一分块；此前收集的内容不清空。非流式响应的空 choices 无后续分块可等待，因此转换为响应格式错误并进入现有重试流程。

备选方案是两种模式都失败，这会继续把合法的 usage/状态分块误判为请求失败；两种模式都跳过则可能把非流式协议异常延迟成含义不清的字段访问或空内容错误。

### 3. 继续使用统一的最终内容校验

流中只出现空 choices 时不在分块循环内立即失败。循环结束后，现有空内容校验负责触发重试，因此正常内容分块可以出现在元数据分块之前或之后。有效 choice 中不含文本的角色或结束分块仍保持无内容片段的既有行为。

非流式路径在取得首个 choice 后继续校验 message/content，并把无文本结果交给既有空内容规则。不会绕过 HTML、已知错误短语、最少字符数或快速错误关键词检查。

### 4. 在 API 调用边界增加回归测试

测试使用可异步迭代 SSE 行的模拟响应，覆盖“内容—空 choices—内容—结束”、仅空 choices、流式顶层 error，以及标准流式成功。非流式用例覆盖空 choices、非列表 choices、非对象首项和非对象 error 值，并保留现有正常成功测试。

断言以公开行为为主：成功内容完整、失败进入 `APIPermanentError` 或既有重试流程、日志包含上游错误文本，并且日志/结果中不出现 `IndexError`、`TypeError` 或 `AttributeError`。

## Risks / Trade-offs

- [上游用空 choices 表示未明示的失败] → 顶层 `error` 仍优先失败；若整个流最终没有文本，统一空内容校验仍会触发重试，避免误报成功。
- [更严格的结构校验拒绝某些专有格式] → 本调用路径声明使用 OpenAI 兼容聊天完成协议；拒绝时提供明确格式错误，便于定位配置或供应商兼容性问题。
- [错误文本变化影响依赖日志文案的代码] → 保留既有 `API返回错误:` 前缀和外层失败包装，只补充此前泄漏的底层异常场景。

## Migration Plan

无需迁移数据或配置。实现后先运行 `tests/test_llm_api.py`，再运行项目完整测试；验证通过即可随应用代码部署。若发现供应商兼容性回归，可回滚该代码提交，现有配置与缓存无需处理。
