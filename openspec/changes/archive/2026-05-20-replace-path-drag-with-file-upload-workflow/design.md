## Context

当前 WebUI 让用户填写或拖拽本地文件/目录路径，但普通浏览器并不稳定提供真实文件路径。此前的路径拖拽尝试已经出现过只拿到文件名、用程序目录拼出伪路径、目录输入无法可靠从文件推导等问题。后端现有业务逻辑仍然依赖本地文件读写，因此新方案需要在“浏览器上传文件”和“后端本地任务运行”之间建立一个稳定的托管工作区。

## Goals / Non-Goals

**Goals:**

- 文件型输入改为浏览器上传文件。
- 上传文件落入后端托管项目工作区，让现有任务逻辑继续读取本地文件。
- 默认输出目录改为 `<runtime_base>/exports/<project_slug>/`，按项目名称分类。
- 提供历史项目选择，用于快速恢复未完成项目的输入文件、输出目标和任务上下文。
- 保留自定义输出目录按钮，满足用户指定其他路径的需求。
- 提供打开目录操作，直接打开默认导出目录或自定义输出目录。
- 清理旧拖拽路径解析、诊断日志和不再使用的路径输入逻辑。

**Non-Goals:**

- 不再尝试通过浏览器拖拽获取真实本地路径。
- 不引入完整项目管理、云存储或远程同步。
- 不重写总结/拆章核心算法，只做输入输出适配。

## Decisions

1. 上传文件复制到后端托管项目工作区。
   - 默认输入根目录为 `<runtime_base>/workspace/projects/<project_slug>/inputs/`。
   - 上传接口返回稳定的上传文件引用和后端本地路径。
   - 原因：现有逻辑可以继续使用本地文件路径，而浏览器不再需要知道用户原始文件路径。
   - 备选方案：继续使用拖拽路径并搜索最近目录。拒绝原因是仍然依赖间接推断，不够稳定。

2. 项目名称作为上传与导出的组织键。
   - 相关工作流页面增加“项目名称”字段。
   - 用户未填写时，单文件工作流从首个上传文件名派生，多文件工作流使用 `project-YYYYMMDD-HHMMSS` 作为默认项目名。
   - 后端在落盘前对项目名称做安全文件名清理。
   - 原因：输出目录需要可读、可预测，且不依赖来源目录。

3. 后端维护历史项目索引。
   - 每个项目工作区保存项目元数据，包括显示名称、slug、创建/更新时间、工作流类型、上传文件清单、默认导出目录、自定义输出目录和最近任务状态。
   - WebUI 启动或打开工作流页时可获取历史项目列表，并按最近更新时间排序。
   - 用户选择历史项目后，前端恢复项目名称、上传文件列表、输出目录设置和可继续任务提示。
   - 原因：上传文件后源路径不再是用户的主要恢复线索，必须由应用提供项目级恢复入口。

4. 默认导出目录由后端统一解析。
   - 默认导出根目录为 `<runtime_base>/exports/<project_slug>/`。
   - 如有必要，工作流可在项目导出目录下创建 `novel-summary`、`article-summary`、`custom-summary`、`chapter-split` 等子目录。
   - 自定义输出目录只覆盖当前任务请求。
   - 原因：普通用户无需再配置路径，高级用户仍可自行选择。

5. 打开目录由后端执行。
   - 前端发送“打开托管目录”或“打开指定目录”请求。
   - 后端校验路径、必要时创建托管目录，并调用本地操作系统打开目录。
   - 原因：浏览器 JavaScript 不能直接打开任意本地文件夹。

6. 任务 API 使用上传引用和输出目标。
   - 新任务请求字段传递上传文件 ID/批次 ID，以及项目名称、自定义输出目录等输出目标。
   - 后端任务适配层在启动任务前把上传引用解析为当前业务逻辑需要的本地路径。
   - 任务状态变化时更新项目元数据，便于历史项目列表显示未完成、运行中、失败或已完成状态。
   - 原因：API 不应依赖浏览器不可获得的客户端本地路径。

7. 替换完成后清理旧路径拖拽逻辑。
   - 共享表单控件移除路径拖拽诊断和文件路径推断逻辑。
   - `/api/utils/resolve-path` 删除或收窄为自定义目录校验专用接口。
   - 原因：保留旧路径机制会继续制造误导和回归风险。

## Risks / Trade-offs

- 上传文件会复制一份，占用磁盘空间 → 限制上传类型和大小，并把文件放入可预测的项目工作区，后续可增加清理入口。
- 现有断点续跑可能依赖源目录缓存 → 使用稳定项目工作区路径，尽量保留当前逻辑可识别的缓存结构。
- 打开目录存在平台差异 → 使用 Python 标准 OS 能力分平台实现，失败时返回明确错误。
- 自定义输出目录仍可能无效 → 任务启动前和打开目录前都做后端校验。
- 项目名冲突可能覆盖旧输出 → 使用相同项目名时视为同一项目；必要时由工作流子目录或任务时间戳隔离新增输出。
- 历史项目元数据可能与实际文件状态不一致 → 加载历史项目时重新校验上传文件和输出目录，缺失项以警告状态展示而不是静默恢复。
