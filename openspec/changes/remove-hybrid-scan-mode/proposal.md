## Why

混合模式依赖小总结先粗筛章节，但小总结不保证与单章文件严格一一对应，导致章节映射失真，并在后续原文精扫阶段形成不可恢复的漏检。随着 LLM 上下文窗口增大、成本下降，直接对选定章节原文精扫更简单、稳定，且可通过 `precise_chapter_batch_size` 平衡速度与 Token 消耗。

## What Changes

- **BREAKING** 移除触发词扫描的混合模式，不再提供“小总结粗筛 + 原文精扫”的扫描路径。
- 触发词扫描统一使用原文章节精扫，并继续支持二次验证、聚合去重、跳过建议、低置信度保留等后续能力。
- 移除或迁移混合模式专属配置：`scan_mode=hybrid`、`coarse_summary_batch_size`、粗筛阶段进度、粗筛启动前置检查和相关用户决策。
- 保留“仅小总结”能力，但其定位回归为小说总结准备能力，不再作为触发词扫描的前置条件。
- 移除触发词扫描粗筛提示词节点；保留精扫、验证、聚合提示词节点。

## Capabilities

### New Capabilities
- 无

### Modified Capabilities
- `trigger-scan-workflow`: 触发词扫描流程从双模式改为仅原文精扫，删除小总结粗筛与混合模式前置条件。
- `webui-workbench`: 触发词扫描配置页移除扫描模式与粗筛批量控件，默认展示精扫批量和二次验证相关控件。
- `configuration-management`: 触发词扫描默认配置不再保存或校验混合模式与粗筛批量字段。
- `workflow-prompt-composition`: 触发词扫描提示词节点不再包含粗筛节点。
- `chapter-processing-granularity`: 仅小总结能力继续保留，但不再作为混合扫描缺失小总结时的补全入口。

## Impact

- 后端扫描配置模型、启动前检查、扫描编排、状态事件、报告快照和配置默认值需要删除或兼容旧混合字段。
- 前端触发词扫描页面、类型定义、启动前检查决策弹窗和默认设置需要改为单一精扫路径。
- Prompt 工作流和默认提示词需要移除粗筛节点及其变量校验。
- 现有测试需更新，删除混合模式断言，新增旧 `hybrid` 配置迁移/拒绝策略、精扫全量扫描和二次验证保留的覆盖。
