## Context

当前触发词扫描同时支持混合模式和精扫模式。混合模式先使用小总结粗筛疑似章节，再读取原文章节精扫；精扫模式直接读取所选范围内的全部原文章节。实践中，小总结生成粒度可由 `summary_batch_size` 合并多章，且 LLM 总结不会严格保留单章边界，导致粗筛结果无法稳定映射回章节文件。

相关实现分布在后端扫描模型与编排、触发词提示词工作流、前端扫描配置页、配置默认值和测试中。仅小总结功能已经作为小说总结流程能力存在，本次不删除该能力。

## Goals / Non-Goals

**Goals:**
- 将触发词扫描运行路径收敛为“原文章节精扫 -> 可选二次验证 -> 聚合/报告”。
- 移除混合模式 UI、配置、提示词节点、启动前置检查和粗筛编排。
- 保留 `precise_chapter_batch_size` 作为速度与 Token 消耗的主要调节项。
- 保留仅小总结任务，但不再把它作为触发词扫描前置补全动作。
- 对旧本地默认配置做低风险兼容，避免打开旧配置时报错。

**Non-Goals:**
- 不改变触发词档案、规则阈值、发现项 JSON schema、二次验证 schema 或报告文件主体结构。
- 不重写章节拆分、小总结生成或项目迁移逻辑。
- 不新增新的扫描模式或成本估算器。

## Decisions

1. 运行时只保留精扫路径。
   - 做法：删除 `config.scan_mode == "hybrid"` 分支，扫描编排始终对所选章节构建原文精扫批次。
   - 原因：混合模式的失败点发生在粗筛章节映射阶段，后续精扫无法恢复漏掉的章节。
   - 备选：保留混合模式但强制 `summary_batch_size=1`。放弃，因为它仍依赖 LLM 总结抽象后的信息，且需要维护双路径。

2. `scan_mode` 对外逐步退场，但报告快照仍写入 `precise`。
   - 做法：前端不再展示扫描模式控件；后端任务请求可省略模式，内部默认归一为 `precise`。报告中保留 `scan_mode: "precise"` 以兼容已有结果视图和历史报告读取。
   - 原因：减少迁移面，同时避免破坏依赖报告字段的代码。
   - 备选：立即删除所有 `scan_mode` 字段。放弃，因为会扩大报告、类型和历史数据兼容风险。

3. 旧配置兼容采用“加载时迁移、运行时拒绝混合”。
   - 做法：配置默认值读取到旧 `hybrid` 或 `coarse_summary_batch_size` 时，保存/返回精扫默认值并忽略粗筛批量；启动或预检请求显式传入 `hybrid` 时返回可理解的错误。
   - 原因：本地保存的旧默认值不应阻止页面打开，但新的扫描任务不应继续进入混合路径。
   - 备选：运行时静默把 `hybrid` 改为 `precise`。放弃，因为用户以为使用了混合模式时，静默改行为不够透明。

4. 粗筛提示词节点从触发词工作流移除。
   - 做法：默认提示词表、工作流节点列表、相关变量校验和测试不再包含 `trigger_coarse_scan`。
   - 原因：没有粗筛阶段后，保留可编辑粗筛提示词会制造无效配置入口。
   - 备选：保留隐藏节点以兼容旧 prompt cache。放弃，旧纯文本缓存可留在磁盘但不再由工作流暴露或使用。

5. 仅小总结入口继续独立存在。
   - 做法：保留 `/api/tasks/novel/small-summary` 和 `stop_after_small_summary` 行为；删除触发词预检中的“生成缺失小总结”决策。
   - 原因：小总结仍是小说总结流程的一部分，只是不再参与扫描准确性链路。

## Risks / Trade-offs

- 旧自动化脚本仍传 `scan_mode=hybrid` -> 后端返回明确校验错误；文档和测试覆盖迁移路径。
- 精扫 Token 消耗上升 -> 通过 `precise_chapter_batch_size` 控制单次批量，用户可缩小扫描范围或降低批量。
- 删除粗筛节点可能让旧 prompt cache 中出现孤立文件 -> 工作流不再列出或读取该节点，保留磁盘文件不影响运行。
- 报告继续保留 `scan_mode` 字段会延迟彻底清理 -> 字段固定为 `precise`，后续可单独提案移除历史兼容字段。

## Migration Plan

1. 更新后端模型默认值和校验：新请求默认精扫，显式 `hybrid` 请求被拒绝，旧保存默认值加载时归一为精扫。
2. 删除扫描编排中的粗筛阶段、小总结覆盖预检和粗筛事件，仅保留章节文件检查、精扫、二次验证和聚合。
3. 更新前端配置页和类型，移除扫描模式、粗筛批量、缺失小总结决策。
4. 更新提示词工作流，移除 `trigger_coarse_scan` 节点和测试。
5. 更新测试与文档，确认精扫覆盖全部选定章节、二次验证仍可开启、旧配置兼容行为清晰。

Rollback 策略：如果需要回退，恢复本变更删除的混合模式分支、UI 控件和提示词节点即可；报告数据因仍保留 `scan_mode` 字段，不需要数据迁移回滚。
