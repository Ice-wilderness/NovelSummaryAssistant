## Why

浏览器拖拽无法稳定暴露真实本地文件路径，继续依赖路径输入会造成文件名-only、伪完整路径和跨环境不一致等问题。项目主要处理小说/文本文件，文件体积较小，改为上传文件和后端托管输出目录能让工作流更可靠、更容易理解。

## What Changes

- 将文件型输入从“填写/拖拽本地路径”改为“浏览器上传文件”，上传后由后端保存在项目工作区中。
- 将目录型输出改为默认使用项目内固定导出目录，并按项目名称分类。
- 保留“选择其他输出目录”按钮，允许用户为单次任务使用自定义输出路径。
- 提供“打开目录”按钮，方便用户直接打开默认导出目录或自定义输出目录。
- 清理旧的拖拽路径解析、诊断日志和不再需要的路径输入代码。

## Capabilities

### New Capabilities

- `file-upload-workflow`: 定义文件上传、上传文件存储、任务输入引用和旧路径拖拽行为清理。
- `managed-project-outputs`: 定义项目命名导出目录、默认输出路径、自定义输出覆盖和打开目录操作。

### Modified Capabilities

- `webui-workbench`: 工作流页面需要从原始路径拖拽/输入控件切换为上传控件和托管输出目录控件。
- `task-runtime-api`: 任务启动 API 需要接受上传文件引用和托管输出目标，而不是要求所有文件输入都来自本地文件系统路径。

## Impact

- 受影响前端：工作流页面、共享表单控件、API 客户端和类型定义。
- 受影响后端：文件上传接口、上传文件存储、任务请求模型、输出目录解析和打开目录接口。
- 受影响业务逻辑：任务启动前需要把上传文件引用转换为当前逻辑可读取的后端本地路径。
- 清理影响：移除或收窄 `/api/utils/resolve-path`、拖拽路径诊断日志和路径拖拽相关 UI。
